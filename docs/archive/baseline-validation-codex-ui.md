# 基准校验文档：Codex 风格对齐检查表

> 版本：v0.1  
> 日期：2026-07-22  
> 用途：发布前确认“形态上接近 Codex 最新界面语言”

---

## 1. 校验方法

- 不追求像素级复刻；
- 校验“信息架构 + 交互节奏 + 可监督性”是否一致；
- 以通过/不通过判定，必须给证据截图或页面路径。

---

## 2. 结构对齐（必过）

| 检查项 | 通过标准 |
|---|---|
| 多任务工作台感 | 有任务入口、历史导航、详情主区 |
| 线程/任务切换 | 不跳出上下文即可切任务 |
| 评审/活动面 | Dev 有事件流与状态面板 |
| 状态可见性 | running/failed/completed 一眼可见 |

---

## 3. 视觉对齐（必过）

| 检查项 | 通过标准 |
|---|---|
| 层级清晰 | 标题、正文、元信息对比明显 |
| 卡片与边框 | 低对比边框，信息块分层明确 |
| 状态色一致 | 状态色语义一致（绿/红/中性） |
| 间距节奏 | 8px 体系，页面不拥挤不松散 |
| 可扫描性 | 首屏可读核心状态，不需深滚动 |

---

## 4. 角色分层校验（必过）

| 检查项 | Ops | Dev |
|---|---|---|
| 宏观进度 | 必须显示 | 必须显示 |
| 报告内容 | 必须显示 | 必须显示 |
| Loop 细节 | 禁止显示 | 必须显示 |
| 错误堆栈 | 禁止显示 | 禁止原始堆栈，显示结构化错误 |

---

## 5. 可观测性校验（Dev）

- [ ] 可见 `current_action`
- [ ] 可见 `micro_route`
- [ ] 可见 `failure_class`
- [ ] 可见 budget 指标
- [ ] 可见 events（最近 N 条）
- [ ] 失败任务可回溯到失败节点

---

## 6. 发布门禁

任一项不通过则不得标记“UI 对齐完成”：

1. Ops 泄露 loop 技术字段
2. Dev 无法定位失败原因
3. 构建失败或关键路由不可访问
4. 信息层级混乱，无法首屏扫描任务状态
