# 需求文档：双视图 UI（Ops / Dev）

> 版本：v0.1  
> 日期：2026-07-22  
> 关联：`spec-ui-codex-alignment.md`

---

## 1. 背景

当前页面“能用但粗糙”，且运营/开发使用同一信息层，导致：
- 运营看到了不必要技术细节（认知负担高）
- 开发看不到关键 Loop 细节（不可监督）

需要拆分为两套视图，并对齐 Codex 最新产品的“指挥台”式工作流。

---

## 2. 功能需求

## FR-1 路由与导航分层
- 系统必须提供 `/tasks/*`（Ops）和 `/dev/tasks/*`（Dev）两套路由。
- 顶部导航必须根据视图模式显示对应入口。

## FR-2 运营视图最小信息面
- 运营详情页仅显示：
  - 任务状态
  - 宏观进度
  - 报告摘要
  - 关键词卡片
  - 失败人话提示

## FR-3 开发视图可观测面
- 开发详情页必须显示：
  - 当前 action 与路由判定
  - 预算/重试/replan 指标
  - 事件流（按时间倒序或正序，至少最近 100 条）
  - 错误分类与提示

## FR-4 统一数据源
- 两套视图必须消费同一 `TaskDetail` API。
- Dev 字段通过可选 `debug` 扩展，不影响 Ops。

## FR-5 状态一致性
- Ops/Dev 看到的 `status/progress/report` 必须一致。
- Dev 不得更改任务执行，仅做“观察层”。

---

## 3. 非功能需求

- NFR-1 可读性：关键信息首屏可见，避免滚动后才看到状态。
- NFR-2 性能：轮询 2s 一次时，页面渲染无明显卡顿。
- NFR-3 兼容：Chrome 最新版可用。
- NFR-4 安全：Ops 禁止显示原始异常/堆栈。

---

## 4. 边界与非目标

- 本轮不做：
  - 设计系统抽离（token 平台化）
  - 多租户权限控制
  - SSE/WebSocket 推流
  - 真实 Douyin MCP 数据接入（已有 M2 规划）

---

## 5. 依赖

- 后端 `TaskDetail.debug` 可选字段
- LangGraph stream 状态写入 task_store
- 现有 `report/progress` 结构稳定

---

## 6. 风险与缓解

- 风险：Dev 事件过多导致 UI 卡顿
  - 缓解：后端截断 events（最近 N 条），前端虚拟滚动可后续加
- 风险：字段演进导致 Dev 页面崩溃
  - 缓解：全部字段可选 + fallback 文案

---

## 7. 需求验收

1. Ops 页面无 loop 术语。
2. Dev 页面可见 loop 指标与事件流。
3. 同一任务在两套页面结果一致。
4. 构建通过，关键路径无 console error。
